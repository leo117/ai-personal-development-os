2. 完整数据架构与数据库模型

基于 PostgreSQL 16 + pgvector + Redis 7 + NetworkX / Neo4j 架构，核心表结构涵盖画像、8态技能状态机、FSRS 记忆调度与原子事件埋点：

-- 1. 用户画像与安全认知档案
CREATE TABLE learners (
    user_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    email VARCHAR(255) UNIQUE NOT NULL,
    target_role VARCHAR(100) NOT NULL,
    agency_score NUMERIC(4,3) DEFAULT 0.500,
    ai_dependency_index NUMERIC(4,3) DEFAULT 0.500,
    helplessness_risk_level VARCHAR(20) DEFAULT 'LOW', -- LOW, MEDIUM, HIGH
    encrypted_privacy_profile BYTEA,                   -- AES-256 加密隐私画像
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

-- 2. 技能状态与 FSRS 记忆调度表
CREATE TABLE learner_competencies (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES learners(user_id) ON DELETE CASCADE,
    competency_id VARCHAR(64) NOT NULL,
    state mastery_state_enum DEFAULT 'UNKNOWN',
    stability NUMERIC(6,2) DEFAULT 1.0,        -- 熟练度稳定性 (天)
    difficulty_fsrs NUMERIC(4,2) DEFAULT 5.0,  -- 个人主观难度 (1~10)
    retrievability NUMERIC(4,3) DEFAULT 1.000, -- 当前可提取性/熟练度
    next_retention_test_at TIMESTAMPTZ,        -- FSRS 调度复习时间
    UNIQUE(user_id, competency_id)
);

3. 核心算法与数学模型

高阶能力 FSRS 遗忘衰减调度模型

R(t) = (1 + F × t / S)^(-w)

当可提取性 R(t) < 0.75 时，自动触发“延迟真实情境微挑战”，通关后更新稳定性 S。

习得性无助与动机救援协议 (SDT)

触发：连续 3 次失败 + 延迟激增。
动作：立即挂起高难度主线，注入确定性 Quick-Win 挑战，归因于策略并恢复自主感。

Scaffolding Guard 拦截器代码实现 (Python)

import re
from typing import Tuple

class ScaffoldingGuard:
    CODE_BLOCK_PATTERN = re.compile(r"```(?:python|javascript|typescript|sql|bash)?[\s\S]*?```", re.IGNORECASE)

    @classmethod
    def filter_response(cls, raw_text: str, allowed_level: int, budget: int, is_rescue: bool = False) -> Tuple[str, bool]:
        if is_rescue and allowed_level >= 3: return raw_text, False
        if allowed_level >= 5: return raw_text, False
        if allowed_level in [1, 2] and cls.CODE_BLOCK_PATTERN.search(raw_text):
            return cls.CODE_BLOCK_PATTERN.sub("*(代码由支架机制折叠，请尝试自行构建骨架)*", raw_text), True
        if budget <= 0:
            return "⚠️ **支架能量已用尽**：请独立完成任务并提交评估。", True
        return raw_text, False

5. 真实任务沙箱、Schema 契约与 REST 接口规范

Authentic Task 核心契约 Schema

任务采用真实评估哲学，包含：task_id, week_number, competency_id, bloom_level, difficulty_score, problem_statement, rubrics (JSON) 与 assistance_budget。

AI 动态自适应出题引擎

支持通过 POST /api/v1/tasks/ai-generate 输入薄弱主题动态生成 Authentic Challenge，并通过 POST /api/v1/tasks/ 自动挂载图谱与自增周次。

核心 REST API 规范清单

端点与方法 主要请求载荷 功能与响应说明
GET /api/v1/tasks/ 无 获取全量挂载任务列表，按周次升序排列。
POST /api/v1/tasks/ai-generate {"topic", "bloom_level", ...} AI 针对弱项自适应生成结构化 Authentic Task 草案。
POST /api/v1/tasks/ {"title", "problem_statement", ...} 创建并持久化任务，自动挂载技能节点与自增周次。
POST /api/v1/tasks/submit {"task_id", "deliverable_content"} 提交交付物进入沙箱评估，触发 8 态跃迁与证据链上链。
POST /api/v1/sessions/turn {"user_input", "requested_level"} 双工作区受控对话，扣减援助能量并触发防包办安全护栏。
